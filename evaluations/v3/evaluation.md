## 필수 검증

### Agent Necessity Test
통과. 일반 규칙으로 파일 복사·분류, 완료 단계 비율 계산, 일정 등록, 고정 모델 호출을 할 수 있다. Agent가 작업 목적과 산출물을 비교하여 어느 단계에 연결할지, 완료 여부와 추가 자료, 계획 변경의 영향 범위를 판단한다는 설계에 필요성이 있다. 독립 평가의 입력 격리와 결과 저장은 주로 오케스트레이션 기능이며 그 자체를 자율적 Agent 판단으로 과대평가하지 않았다.

### Workflow Walkthrough
사용자 목표/공고 → 단계·산출물·완료 조건 → 사용자 작업 메시지 및 관련 자료 탐색 → 기존 단계 연결 또는 계획 변경/대안 시험 분기 → 영향 단계 재확인 → 로그·개요·완료율 갱신 → 링크·완료율·남은 일 점검 → 필요시 공개 보고서. 검증 실패 후 수정·재검증 방식은 불명확하다.

독립 평가: 제출본·공통 기준 고정 → 페르소나별 지정 모델에 새 세션/제한 입력 → 개별 결과·대상 버전 저장 → 모두 확정되면 비교. 모델 오류, 점수 범위/합계 오류, 기준 변경에 따른 버전 간 비교 가능 여부는 명확하지 않다. 평가 결과를 진행 계획에 반영할지 여부도 별도 사용자 의사결정이 필요하다.

### Outcome Verification
완료율은 단계 수 비율이며 시간·난이도 비율이 아니다. 계획 단계가 추가/삭제되면 분모가 변할 수 있으므로 완료율 감소 자체를 진행 후퇴로 해석하지 않아야 한다. 완료율과 단계 상태·자료 링크·남은 일 검증은 명시. 오류 감지 후 수정 대상/재검증, 평가 기준별 점수 합계와 근거 검증은 미정의.

### Feasibility Audit / Adversarial Review
지정 폴더, 버전 식별, 구조화된 계획/로그, 접근 제어, 모델 API는 구현 가능한 구성이다. 실제 모델 정확성과 비용·권한·캘린더 연동을 검증한 것은 아니다. 프로젝트를 함께 보여준다는 것은 프로젝트 간 자원/일정 최적화와 다르므로 해당 기능이 구현됐다고 가점하지 않으며 요구사항으로 강제하지도 않는다. 외부 상용 서비스 기능을 이번에는 새로 조사하지 않았으므로 시장 차별성을 확정하지 않는다.

## 화면 시안
- parallel-project-plans: 프로젝트별 단계와 목표일, 완료율을 일관된 구조로 표시. 단계 수 기반 지표라는 해석을 화면에서 알기 쉽게 하는 것이 좋다.
- project-progress-reviews: 현재 버전과 과거 평가 대상 버전을 명확히 분리.
- project-review-comparison: 기준별 점수와 근거의 모델별 차이를 읽기 좋게 제시. 화면 속 예시 점수·인터뷰는 실제 검증 데이터로 인정하지 않음.
- project-agent-settings / editor: 진행·독립 평가·검수의 역할과 모델, 공통 입력을 설명. 초기 사용자의 설정 부담과 기능 분산 우려.

## 예상 심사위원 질문
1. 일반적인 AI 에이전트에 프로젝트 폴더와 지침을 주는 것보다 무엇을 더 안정적으로 수행하는가?
2. 완료 기준이 변경되면 이전에 완료한 단계와 후속 산출물은 어떻게 처리하는가?
3. 완료율이 50%라고 해서 실제 시간의 절반이 끝난 것인가?
4. 작업 메시지와 파일의 근거가 상충하면 무엇을 우선하는가?
5. 독립 평가 중 한 모델이 실패하거나 점수가 모순되면 어떻게 하는가?
6. 독립 평가 및 검수 결과는 현재 계획과 어떻게 연결되는가?
7. 5분 발표에서 어떤 단일 문제와 핵심 작동 사례를 전달하는가?

## 개선 권고 (현재 점수에 미반영)
- P0: 계획-작업-산출물-재계획을 주 시연으로 고정하고, 검증에서 불일치를 발견하면 관련 단계/로그를 수정하고 다시 확인하는 루프를 명시.
- P1: 계획 변경에 따른 완료 기준 버전·기존 완료 철회·후속 영향, 단계 완료율 해석을 구체화.
- P1: 독립 평가/검수는 선택 가능한 보조 기능으로 배치. 평가 요청, 동일 입력, 세션 격리, 버전 저장, 실패 처리, 점수 검증 및 사용자 선택에 따른 계획 반영을 명시하되 무조건 자동 반영하지 않음.
- P2: 최종 발표에서 대시보드와 평가 설정 화면의 비중을 제한하고, 계획 변경의 전후 상태와 근거를 보여줌. 불필요한 기능 추가는 하지 않음.

## 평가 한계 및 제출 요건
최종 PDF가 V3 폴더에 없으므로 10페이지 제한 및 AI 사용 범위 기재 여부는 채점 보류. 현재 문서는 기획안이며 모델 실행, 자동 기록 갱신, 캘린더 연동은 미구현으로 표시되어 있다. 구현 부재 자체에 감점하지 않았다. HTML 시안을 실행하지 않았으며 V3가 연결한 이전 버전의 상세 화면은 재열람하지 않았다. 과거 평가를 알고 있는 같은 대화의 평가자이므로 완전한 블라인드/독립 모델 평가는 아니다. 이전 평가 파일을 열거나 이전 점수에 맞춰 조정하지 않았다. 실제 수상 가능성/순위 추정 불가. 외부 서비스 및 기술의 최신 기능을 별도로 검색하지 않아 시장 차별성은 단정하지 않는다.
