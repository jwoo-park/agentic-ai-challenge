- 근거: [V1](../v1/evaluation.md), [V2](../v2/evaluation.md), [V3](../v3/evaluation.md) 확정 보고서 및 각각 평가 당시 확인한 기획안과 시안.

## 기획 방향 및 쌍대 비교

- V1: GitHub 커밋·회의록·실험 자료를 날짜별 일지로 만들고 의미적으로 관련 작업 블록을 묶는다. 담당 예정→실제 기여 확인→CV/공개 소개라는 핵심 가치가 집중되어 있다. 다만 능동적 행동 선택 및 복구가 불명확하다.
- V2: 지정 프로젝트 폴더, 최신 개요, 날짜별 로그, 자료 관리, Markdown 공개 보고서 편집 및 승인 흐름이 구체적이다. 중복 자료·반복 요청 처리가 발전했다. V1의 작업 블록 연결과 출력물 근거 점검의 강조는 상대적으로 약하다.
- V3: 프로젝트 시작부터 계획을 수립하고 실제 작업을 단계와 완료 조건에 연결하며, 명시적인 방향 변경과 단순 시험을 구분하고 영향 단계 및 남은 일을 갱신한다. 정리 종료 시 링크·완료율·남은 일 일관성을 점검한다. 독립 평가·검수 프리셋은 별도의 유용한 기능이나 멀티모델 사용 자체는 Agentic 점수의 근거가 아니다. V3는 V2의 내부·공개 화면을 명시적으로 참조하므로 해당 기능이 삭제되었다고 단정하지 않는다.

V1 대 V2: 대회 배점상 사실상 동급. V1은 문제와 기여의 핵심 서사가 집중되고, V2는 실제 이용 및 자료 관리가 구체적이다.
V1 대 V3: V3 우세. 계획을 기준 상태로 두고 실제 작업에 따라 판단·행동·재계획이 이어진다. V1의 개인 기여 근거 및 작업 간 의미 연결은 보존할 가치가 있다.
V2 대 V3: V3 우세. 재계획과 종료 점검이 핵심 개선이며 범위와 전달력은 V2가 더 안정적이다.

## 남은 위험 및 권고
V3를 제출용 기반으로 선택한다. 기능의 전면 제거보다 핵심 시연과 보조 기능의 위계를 정하는 것이 중요하다. 사용자 목표→계획/완료 조건→실제 작업 및 산출물→방향 변경 판단→재계획→일관성 검증을 주 시연으로 삼고, 독립 평가와 검수는 필요 시 실행하는 보조 기능, 공개 보고서는 기록 재사용의 결과로 설명한다. V1의 팀 결정·담당 예정·개인 기여 구분과 V2의 공개 승인/원본 연결을 유지한다. 우선 보완할 사항은 검증 실패 후 수정·재검증, 상충하는 근거 해결, 완료된 단계의 기준 변경과 후속 영향, 모델 실패/점수 검증, 범용 Agent와의 구체적 비교이다. 여러 프로젝트의 일정 최적화나 추가 화면을 새 필수 기능으로 요구하지 않는다.

## 한계
동일한 평가자의 문서 기반 정성 비교이며 통계적으로 독립적인 모델 간 비교가 아니다. 각 버전 스트레스 테스트의 질문 구성이 다르므로 통과 개수를 공통 벤치마크 성능처럼 직접 비교하지 않는다. 시장 경쟁 서비스나 실제 모델 실행, 최종 제출 PDF는 이번 비교에서 검증하지 않았다. 실제 수상 확률은 추정하지 않는다.
