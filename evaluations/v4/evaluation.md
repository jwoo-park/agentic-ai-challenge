## 필수 검증

Agent Necessity Test: 통과. 저장된 관계 조회, 파일 분류, 상태 계산은 규칙 기반으로 가능하다. 사용자 요청의 의미를 분석해 명시되지 않은 영향 관계를 찾고, 작업 사실과 계획 변경을 구별하며, 기존 완료 상태 및 공식 제출 조건을 재판단하는 기능이 Agent의 필요성을 뒷받침한다. 범용 Agent 대비 우월성은 검증되지 않았다.

Workflow Walkthrough: 작업/결정 해석 → 연결 자료 우선 확인 → 지정 폴더 추가 검색 및 종료 → 계획 조건, 리허설 항목, 산출물 준비 상태 갱신 → 완료 조건 판단 → 저장 후 재조회 및 요약. 현장 시연 변경과 별도 영상 제출 요건 구분이 중요한 판단 사례다. 사용자가 요청하기 전 초안 내용을 자동으로 수정했다고 간주하지 않는다. 자료 있음/설명 추가 필요/작성 예정은 서로 구분한다.

Outcome Verification: 계획 상태/남은 일/완료율을 재조회하고, 배점 범위와 총점도 검증한다. 의미적으로 잘못 연결한 자료나 누락한 수정 위치를 어떤 근거로 발견하고 수정하는지 더 명확해야 한다. 단계 완료율은 시간이나 난이도 비율이 아니다.

Feasibility Audit: 지정 폴더, 구조화된 계획 및 자료 관계, 문서 검색/편집, 모델별 세션은 기존 기술로 구현할 수 있는 구성이다. 실제 정확도, 지연, 비용, 접근 권한, 문서 편집 안전성을 검증한 것은 아니다. 비교 계획의 빠뜨린 수정 위치·잘못 완료 처리한 단계·사용자 재지정 횟수는 구체적이다. 정답 영향 목록 및 작업 완료 기준을 미리 정의하고 같은 입력·권한·모델 조건에서 비교할 필요가 있다.

Adversarial Review: 관계가 명시되지 않은 파일의 누락 위험, 기존 자료의 잘못된 귀속, 재조회 후 불일치 수정, 계획 변경 권한과 사용자 의도 확인, 공개본 정정이 남은 핵심 질문이다.

## 예상 질문 및 개선 권고
1. 범용 Agent에 같은 계획과 폴더를 주는 것보다 어떤 작업을 더 정확하고 일관되게 처리하는가?
2. 기존 계획에서 연결되지 않은 간접 영향은 어떻게 찾아내며 누락을 어떻게 확인하는가?
3. 사용자의 진행 보고와 문서가 상충하면 어떤 조건에서 보류 또는 확인 질문을 하는가?
4. 저장 후 재조회에서 계획/로그 불일치가 발견되면 어떻게 수정하고 재검증하는가?
5. 자료가 존재한다는 상태와 실제 산출물에 반영됐다는 상태를 어떻게 확인하는가?
6. 잘못된 연결이나 공개 문안을 사용자가 어떻게 정정하는가?

P0: 검증 불일치 발견→수정 대상 선택→재조회→미해결 표시의 루프를 명시.
P1: 간접 영향 탐색과 충돌/보류 조건을 명시하고, 범용 Agent와 비교 시 정답 영향 목록을 정의.
P2: 최종 제출본에서 영상→HTML 전환 전후를 한 사례로 보여주고, 문제 해결 및 소개/평가 기능은 보조 기능으로 제시. 추가 기능 확장은 우선하지 않는다.

## 평가 한계
최종 제출 PDF가 V4 폴더에 없어 페이지 제한 및 AI 활용 범위 기재는 채점 보류했다. 화면의 예시 데이터는 실제 검증 성과로 인정하지 않았다. HTML 및 실제 모델은 실행하지 않았고 최신 외부 경쟁 서비스를 별도로 조사하지 않았다. 같은 대화의 평가자이므로 완전한 블라인드/독립 모델 평가는 아니다. 이전 평가 보관소는 절대평가 점수 확정 이후 사용자의 비교 요청을 수행할 때만 열었다. 실제 심사 점수 및 수상 확률은 추정하지 않는다.
