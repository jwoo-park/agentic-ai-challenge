# v4 에이전트 동작과 판정 기준

[v4 기획안](README.md)

## 판단에 쓰는 정보

| 정보 | 사용하는 내용 |
| --- | --- |
| **작업 로그** | 날짜, 사용자가 기록한 작업과 결정, 연결된 파일과 버전, 확인된 팀·개인 역할 |
| **현재 계획** | 목표와 목표일, 단계와 완료 조건, 후속 작업에 필요한 자료 |
| **산출물** | 기획안·발표 자료 등의 현재 버전, 연결된 근거, 공개가 확정된 문안과 첨부 |
| **문제와 해결** | 발생한 문제, 대응, 결과를 확인한 기록, 사례를 사용하는 결과물 |

작업 범위는 사용자가 지정한 프로젝트 폴더와 연결 자료다. 파일 분류, 단계 완료율 계산, 자료 링크 저장은 일반 프로그램이 처리한다. 계획에 이미 명시된 연결은 저장된 관계로 조회한다. 에이전트는 사용자의 말에서 **작업 사실과 바뀐 결정을 구분하고, 관계가 드러나 있지 않은 자료에서 어떤 계획 조건과 결과물이 영향을 받는지** 판단한다.

## 기록을 처리하는 순서

1. **요청을 해석한다.** “HTML도 시험해봤어”는 작업 기록으로 남긴다. “현장 시연을 HTML로 바꾸자”는 시연 방식 변경으로 기록한다.
2. **연결된 정보부터 확인한다.** 현재 시연 단계, 리허설 항목과 연결된 발표 초안을 읽는다. 관계를 확인하기 어렵다면 사용자가 지정한 자료에서 같은 작업이나 발표본을 찾는다. 영향 범위가 확인됐거나 접근 가능한 자료에서 확인이 어려우면 탐색을 마치고 확인된 내용과 미확인 항목을 표시한다.
3. **영향받는 부분을 갱신한다.** 영상 재생을 전제로 한 리허설 항목은 HTML 동작 확인으로 갱신한다. 발표 초안의 시연 설명과 해당 할 일에는 바꿔야 할 내용을 연결한다. 공고에 별도 제출용 영상 요건이 연결되어 있다면 그 조건도 확인해 제출 작업을 표시한다.
4. **완료 조건을 확인한다.** 과거에 만든 영상은 작업 로그에서 볼 수 있다. 현재 계획에서는 HTML 기본 흐름과 예외 화면을 확인한 기록으로 시연 준비를 판단한다. 예외 화면 확인이 남아 있으면 해당 단계에 남은 일로 기록한다.
5. **저장하고 결과를 확인한다.** 새 로그·계획과 관련 자료의 연결을 저장한 뒤 다시 읽어본다. 현재 단계, 남은 일, 단계 완료율이 같은 계획을 가리키는지 점검한다. 사용자에게 변경한 단계와 확인할 내용을 요약한다.

## 충돌과 재확인

| 상황 | 처리 |
| --- | --- |
| 사용자 요청이 현재 확인한 자료와 충돌함 | 현재 계획의 조건과 최신 자료의 버전을 대조한다. 사용자가 보고한 작업은 로그에 남기고, 완료를 뒷받침할 근거가 부족하면 해당 부분을 확인할 일로 표시한다. |
| 이미 끝난 단계의 조건이 바뀜 | 새 조건을 충족하는 자료가 있는지 먼저 확인한다. 점검할 사항이 남으면 해당 단계를 진행 중으로 갱신하고 직접 연결된 후속 준비를 다시 살핀다. |
| 수정 자료가 나중에 들어옴 | 바뀐 조건을 그 자료에서 다시 확인한다. 조건을 충족하면 해당 단계와 남은 일을 갱신하고 개요를 다시 점검한다. |
| 로그·계획 저장에 실패함 | 마지막으로 확인한 상태와 저장이 필요한 변경을 보여준다. 다시 요청받으면 같은 작업 기록이 있는지 확인하고, 빠진 변경을 반영한 뒤 결과를 다시 읽는다. |
| 산출물에서 설명이 누락됨 | 준비 중인 할 일에 연결된 자료와 추가할 내용을 표시한다. 사용자가 초안 반영을 요청하면 지정 폴더의 초안을 편집하고 어느 버전에 들어갔는지 확인한다. |

단계 완료율은 **현재 계획에서 완료한 단계 수 ÷ 전체 단계 수**다. 상태 변화가 있을 때 단계 수와 완료 조건을 함께 설명해, 자료가 이미 생긴 일과 현재 목표에 충분히 반영된 일을 구분할 수 있게 한다.

사용자 요청과 공고의 조건이 반영 후에도 각각 충족되는지 확인한다. [시연 방식 변경 후 재검증](revalidation.md)에서는 필수 제출 작업 누락을 발견하고 복구한 뒤 남은 일과 단계 완료율을 다시 확인한다.

## 문제 해결 사례를 다시 쓰는 방식

작업 로그에서 **문제, 대응, 결과 확인**을 근거와 함께 연결한다. 목차 링크 이동 오류의 경우 링크가 열리지 않은 상황, 연결 위치 수정, 수정한 시안에서 다시 이동해 확인한 결과가 사례가 된다. 진행 화면에서 이 사례를 열 수 있고, 발표 자료의 할 일에서는 같은 사례를 참조한다. 공개용 소개에는 사용자가 고른 사례와 문장만 반영한다.

## 독립 평가를 연결하는 방식

사용자가 평가를 요청하면 지정한 제출본과 평가 기준을 고정한다. 각 모델에는 공통 제출본과 기준, 해당 페르소나의 지시를 전달하고 결과는 별도 기록으로 받는다. 해당 버전의 평가가 모두 확정되면 기준별 점수와 근거를 비교한다. 배점 범위와 총점을 확인하고, 한 모델의 요청이 실패했다면 같은 제출본과 기준으로 그 평가만 다시 시도한다.

사용자가 보완 의견을 채택하면, 관련 계획에 이미 있는 일인지 찾아 연결한다. 필요한 새 작업은 제안하고 사용자가 적용하겠다고 할 때 계획에 반영한다.

## 비교 시연 기준

같은 프로젝트의 계획, 파일과 채팅을 파일 접근이 가능한 범용 에이전트와 이 기획의 흐름에 순서대로 준다. 영상 방식에서 HTML로 바꿨을 때 **빠뜨린 수정 위치, 잘못 완료 처리한 단계, 사용자가 다시 지정해야 한 항목 수**를 비교한다. 이후 초안과 문제 해결 사례에서 원본 근거를 열 수 있는지 확인한다.
