# 에이전트 동작과 시연 기준

[v3 기획안](README.md)

## 작업에 사용하는 정보

| 정보 | 저장하고 쓰는 내용 |
| --- | --- |
| 현재 계획 | 목표, 예상 기간과 목표일, 단계별 완료 조건, 예정된 산출물, 순서 |
| 실제 작업 | 채팅에 남긴 작업과 결정, 날짜, 연결된 계획 단계, 관련 자료 |
| 프로젝트 자료 | 유형, 위치, 참조한 버전, 로그나 보고서와의 연결, 공개 승인 여부 |
| 일정 | 목표일, 확인된 외부 마감, 등록한 일정의 연결 정보 |
| 에이전트 프리셋 | 프로젝트에 적용한 프리셋, 진행·독립 평가·검수 블록별 페르소나와 모델, 프롬프트, 공통 평가 기준과 출처 |
| 작업 방식 | 사용자가 저장을 요청한 회고와 관련 기록을 참고해 다음 계획을 제안하는 확장 기능 |

프로젝트가 지정되면 해당 프로젝트의 계획과 기록부터 읽는다. 외부 자료는 사용자가 선택한 위치에서 참조하거나 사본을 가져올 수 있다. 변경과 저장은 지정된 프로젝트 폴더 안에서 처리한다. 파일 분류, 복사, 완료율 계산과 일정 등록은 정해진 규칙으로 처리한다. 에이전트는 **이번 기록이 어느 계획 단계에 해당하고, 어떤 후속 자료를 확인해야 하며, 어느 상태를 갱신할 수 있는지**를 결정한다.

## 저장한 프롬프트와 독립 평가 범위

1. 사용자가 AI에 진행·독립 평가·검수를 요청하면 현재 프로젝트 프리셋의 해당 블록과 저장된 페르소나 설정을 읽는다.
2. 진행 블록은 현재 프로젝트의 계획, 기록과 산출물을 읽어 진행 상황을 갱신한다. 검수 블록은 지정한 체크리스트로 형식, 필수 항목과 링크를 확인한다.
3. 독립 평가를 준비할 때는 같은 버전의 제출본과 공통 평가 기준을 고정한다. 각 페르소나에 지정한 모델로 새 세션을 열고, 그 세션의 입력은 제출본, 공통 평가 기준, 해당 페르소나의 역할·목표·추가 지시로 구성한다.
4. 각 결과는 제출본과 기준의 버전, 기준별 점수, 제출본의 근거, 보완 의견을 개별로 저장한다. 해당 버전의 모든 평가가 확정되기 전까지 사용자에게는 완료 상태만 보여준다. 확정된 뒤에는 프로젝트 진행 화면 하단에서 같은 기준에 대한 점수와 근거를 나란히 읽을 수 있다.
5. 새 기획안 버전이 생기면 화면 상단의 현재 버전을 갱신한다. 기존 결과의 평가 대상 버전은 평가 당시 저장한 값으로 표시하고, 사용자가 해당 버전을 펼쳐 다시 확인할 수 있게 한다.

## 요청별 행동 선택

| 상황 | 에이전트가 판단하는 기준과 행동 |
| --- | --- |
| 사용자가 목표와 대략적인 기간을 제시함 | 목표를 주요 단계로 나누고 예상 산출물을 연결한다. 시작일이나 목표일이 정해지면 날짜를 계산한다. 따로 확인할 제출 조건이 있으면 연결된 공고를 읽는다. |
| 기록이 현재 계획의 한 단계와 일치함 | 작업 목적과 관련 산출물을 기준으로 단계에 연결한다. 단계의 완료 조건을 충족하면 완료로, 일부만 마쳤으면 현재 진행 내용으로 기록한다. |
| 어떤 단계에 속하는지 모호함 | 파일과 연결된 메모에서 실제로 한 일을 더 확인한다. 확인 가능한 부분부터 로그에 남기고, 진척은 기존 상태에서 이어간다. |
| 사용자가 명시적으로 계획을 바꿈 | 바뀐 단계와 완료 기준을 반영한다. 영향을 받는 일만 다시 확인해 현재 위치, 남은 일과 완료율을 갱신한다. 목표일 조정이 필요하면 제안하고 사용자 결정에 따라 반영한다. |
| 사용자가 계획에 없던 대안을 시험함 | 시도를 로그와 자료 목록에 남긴다. 이후 채택이 확인되면 해당 계획 단계에 반영한다. |
| 보고서 초안에 개인 기여나 성과가 들어감 | 연결한 자료가 문장의 역할, 결과와 수치를 뒷받침하는지 확인한다. 확인된 범위에서 설명하고 공개 자료는 사용자가 확정한다. |

## 대표 시연 · 공모전 발표를 준비하는 날

**입력.** 프로젝트의 4개 계획 단계 중 기획안 확정이 끝났다. 시연 준비 단계에는 “시연 영상 초안 만들기”가 있다. 사용자가 “오늘 HTML 시안 연결했어. 영상 대신 이걸로 현장 시연하자. 예외 화면은 확인 중이야”라고 말한다.

1. 에이전트는 프로젝트 폴더에서 관련 HTML 시안을 찾고 사용자 메시지를 근거로 시연 방식 변경을 반영한다. HTML 시안 준비 단계의 완료 조건에는 주요 시연 흐름과 예외 화면 확인을 둔다.
2. 날짜별 로그에는 HTML을 연결한 작업과 시연 변경 결정을, 자료 목록에는 실제 HTML을 연결한다. 현재 계획에서는 시연 준비를 진행 중으로 두고 예외 화면 확인을 남은 일로 표시한다.
3. 현재 계획의 4단계 중 1개가 완료되었으므로 완료율은 25%다. 사용자가 예외 화면 확인까지 마쳤다고 기록하면 시연 준비 완료를 반영해 50%로 갱신한다.
4. 프로젝트 소개 초안을 만들 때 날짜별 로그에서 시연 방식 변경과 그 근거를 찾고, 사용자가 선택한 HTML·캡처·최종 발표 자료를 공개본에 포함할 수 있게 한다.

## 완료 확인과 예외 상황

- **정리 요청 종료** · 날짜별 로그와 연결된 자료가 열리는지, 완료율이 현재 계획의 단계 상태와 일치하는지, 완료된 일을 남은 일로 다시 표시하지 않는지 확인한다.
- **같은 날 다시 요청** · 이미 기록한 작업과 자료를 확인하고 그날 새로 생긴 내용과 근거를 추가한다.
- **자료 접근 실패** · 확인된 채팅과 자료부터 처리하고, 해당 파일은 확인할 항목으로 남긴다. 파일을 열어야 완료 여부를 판단할 수 있다면 기존 진행 상태를 유지한다.
- **일정 등록 실패** · 프로젝트 계획에서 목표일과 제안한 시간을 확인할 수 있고, 캘린더 등록 성공 여부를 따로 표시한다. 사용자가 다시 등록할 때 기존 연결부터 확인한다.
- **공개 초안 검토** · 표시된 개인 역할과 결과가 연결된 기록의 범위인지 확인한다. 사용자가 확정한 문안과 자료를 공개본에 반영한다.

## 비교 검증 계획

같은 계획, 폴더와 작업 메시지를 두 방식에 순서대로 준다. 하나는 파일 접근과 수정이 가능한 범용 에이전트이고, 하나는 이 기획의 워크플로다. 중간에 시연 방식 변경을 추가하고, 사용자가 계획과 로그를 함께 갱신하라고 따로 말한 횟수, 잘못 연결한 단계 수, 완료 후 소개에 쓸 자료를 다시 찾아야 한 횟수를 비교한다.
