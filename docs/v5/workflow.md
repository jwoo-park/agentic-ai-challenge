## 프로젝트 기록과 변경 점검

| 단계 | 에이전트가 판단하는 내용 | 처리 결과 |
| --- | --- | --- |
| **한 줄 기록** | 사용자가 끝낸 작업, 팀이 합의한 변경, 검토 중인 안을 구분한다. | 날짜와 원문을 보존하고 근거가 되는 자료를 연결한다. |
| **영향 범위 탐색** | 현재 계획에서 직접 연결된 할 일을 확인한다. 연결만으로 설명이 부족하면 지정 폴더에서 관련 공고·발표 초안·리허설 자료를 탐색한다. | 영향을 받는 작업과 초안의 수정 위치를 표시한다. |
| **반영과 재검증** | 새 완료 조건을 뒷받침하는 자료를 찾고, 임시 반영사항을 원 요청과 공고에 다시 대조한다. | 필수 작업이 빠졌으면 기존 계획에서 기한과 자료 조건을 복원하고, 남은 일과 완료율을 다시 확인한다. |
| **공개용 소개 준비** | 역할, 문제와 대응, 확인 결과를 뒷받침하는 작업 기록을 고른다. | 소개 초안에서 주장마다 연결된 근거를 확인한다. 사용자가 승인한 문안과 자료를 공개 대상으로 확정한다. |

자료 분류, 이미 저장된 연결 조회, 단계 완료율 계산과 화면 표시는 프로그램이 처리한다. 현재 계획과 공고의 근거가 충돌하거나 자료에 접근하기 어려우면 마지막으로 확인한 상태와 미확인 항목을 보여준다.

## AI가 구성하는 프리셋

창업대회·연구실·장학금 같은 유형을 바탕으로, 진행 정리·독립 평가·검수에 필요한 모델과 지시를 AI가 구성한다. 예를 들어 “시연 검증을 중점으로 봐줘”라고 요청하면 평가 블록에 문제 정의를 보는 심사위원과 시연 근거를 보는 심사위원의 지시를 준비할 수 있다. 사용자는 저장된 설정에서 각 역할, 모델, 프롬프트를 확인하고 필요한 프로젝트에 연결한다. 평가용 프리셋은 요청한 평가를 시작할 때 사용한다.

## 독립 평가 요청에서 결과 비교까지

| 단계 | 동작과 확인 기준 |
| --- | --- |
| **입력 고정** | 제출본과 공통 기준, 심사위원별 모델과 지시를 평가 묶음에 저장한다. 시작 후 프리셋을 바꿔도 진행 중인 평가는 시작 시점의 설정을 사용한다. |
| **세션 분리** | 각 세션에는 제출본, 기준, 그 심사위원의 설정만 전달한다. 이전 대화나 다른 심사위원의 결과를 세션 입력에 포함하지 않는다. |
| **결과 수집** | 결과를 심사위원별로 저장한다. 모델을 연결한 실행에서는 배점 범위, 총점 합계와 근거의 원문 위치를 검증한다. 조건을 충족한 결과를 완료로 집계한다. |
| **오류 처리** | 모델 응답이 없거나 결과 형식이 올바르지 않으면 같은 입력과 설정으로 해당 세션만 재시도한다. 계속 실패하면 어느 세션이 미완료인지 표시하고 재실행할 수 있게 한다. |
| **공개와 활용** | 시작할 때 정한 평가가 모두 완료되면 제출본 버전과 함께 심사위원별 점수와 근거를 표시한다. 사용자가 채택한 판단은 관련 계획 단계에 연결하거나 수정 후보로 제안한다. |

사용자가 제출본이나 기준을 바꿔 평가하면 별도 평가 기록을 만든다. 이전 결과는 당시 버전의 기록으로 남겨 다시 열 수 있다. 시안에서는 세션 분리와 결과 비교를 예시 데이터로 확인할 수 있으며, 모델 응답의 배점·원문 검증은 연결 후 검증할 항목이다.

## 제출 시연에서 확인할 것

- 한 가지 변경 요청으로 계획과 완료 조건, 발표 초안의 수정 후보가 연결되는지, 공고 재확인에서 누락된 필수 작업을 찾아내는지 본다.
- 제출본과 기준을 각각 한 번 입력해 평가를 시작한다. 첫 세션이 끝난 상태에서는 점수와 근거가 표시되지 않고, 모든 세션이 끝난 뒤 한 화면에 모이는지 확인한다.
- 프리셋에서 심사위원마다 저장된 모델과 프롬프트를 확인하고, 평가 기록을 다시 열었을 때 같은 제출본 버전의 결과가 보이는지 확인한다.
